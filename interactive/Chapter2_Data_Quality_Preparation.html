Section 1

What is data quality?

Data quality is how reliable, accurate and usable data is for decision-making. "Good" always depends on the use: a customer address that's fine for a newsletter may be useless for delivering a parcel.

Why it matters

Reliable analysis, better decisions, lower organizational risk.

Common challenges

Missing values, duplicates, inconsistent formats, outdated data, data silos.

Improved through

Clear standards, regular validation, automated checks, periodic audits, staff awareness.

Real-world exampleIncomplete sales data hides trends → a retailer under-orders a bestseller and over-orders a slow product. Same software, same staff — just worse data.

Measuring quality: KPIs

Completeness rate

% of required fields filled

Error rate

% of fields incorrect / invalid / inconsistent

Duplication rate

% of duplicate records

Validity rate

valid ÷ checked × 100

Timeliness

% of data up to date when needed

Data quality score

composite of the above

How are these computed?

60 fields = 10 rows × 6 columns. Completeness = non-empty / all. Error rate = fields that break a rule (discharge before admission, diagnosis not in {Flu, Asthma, Diabetes, Hypertension}, invalid date) / all. Duplication = rows identical to an earlier row / rows. Timeliness = rows with an admission date / rows. Score = average of completeness, (100 − error), (100 − duplication), timeliness.

completeness = df.notna().sum().sum() / df.size * 100
duplication  = df.duplicated().mean() * 100
bad_dx       = ~df['Diagnosis'].isin(['Flu','Asthma','Diabetes','Hypertension'])
bad_dates    = pd.to_datetime(df['Discharge']) < pd.to_datetime(df['Admission'])
Section 4

Challenges & improvement strategies

Challenge

Data silos

Sales in one system, customer service in another — no complete view of the customer. Fix: shared platforms, interoperable systems, a central warehouse.

Challenge

Inconsistent formats

MM/DD/YYYY vs DD/MM/YYYY; km vs miles. Fix: standardize formats, units and conventions.

Challenge

Resource constraints

Too few people, tools or budget. Fix: automate routine checks, prioritize critical issues.

Strategy

Automated validation

Checks run as data is entered/processed — e.g. checkout validates addresses; banks validate transactions in real time (fraud detection).

Strategy

Data quality audits

Scheduled structured reviews — e.g. an insurer audits customer data for regulatory compliance; findings drive continuous improvement.

Data profiling — the diagnosis before the cure

Profiling analyses a dataset to understand its structure, patterns, anomalies and quality issues before cleaning or ETL. It splits into two investigations:

Column analysis

Each field on its own: cardinality, data types & patterns, domains, value distributions.

Structure analysis

Relationships between fields: functional dependencies, unique column combinations, inclusion dependencies.

Column profiler

Click a column header to profile it. The table contains a duplicate row, a suspicious amount and an invalid email — can you find them with the profiler?

Structure analysis

A → B: every row with the same A must have the same B (e.g. Customer ID → Name, Price × Quantity → Total). A violation means the same key gives different answers — the data can't be trusted.

Check Customer ID → Name

When no single column identifies a row, a combination may (a composite key).

Section 6

Cleaning I — missing values

The cleaning process: Profile → Transform → Validate → Output. For gaps you have three options:

Imputation

Fill with mean / median / mode, or predict with a model (Decision Tree, Random Forest, KNN).

Deletion

Drop records when the field isn't critical or too much is missing to impute reliably.

Flagging

Keep the row, add a was_missing flag and treat it separately in analysis.

Section 8

Cleaning III — noise vs. outliers

Noise

Random variation or error with no meaningful pattern — sensor jitter, typos, measurement error. Handle with smoothing, deletion of nonsense rows ("abcxyz"), or unit transformation.

Outlier

A point far from the rest. It may be an error (a typo of 3000 instead of 300) or the most interesting fact in the data (fraud!). Use domain knowledge before removing — consider imputation, segmentation, visualization.

Hourly temperature sensor

smooth = temp.rolling(window=5, center=True).mean()      # mean smoothing
z = (temp - temp.mean()) / temp.std()
outliers = temp[z.abs() > 2.5]
# IQR rule (robust):  q1, q3 = temp.quantile([.25, .75]); iqr = q3 - q1

Transformation — scaling, encoding, binning, features

Scaling — same range for all features (min-max, z-score)
Encoding — categories → numbers (one-hot)
Binning — continuous → intervals (age groups)
Feature generation — ratios, interactions (income / age)
Feature scaling

Standardization (z-score): Z = (X − μ) / σ → mean 0, sd 1. Normalization (min-max): X' = (X − min) / (max − min) → [0, 1]. Without scaling, income (tens of thousands) dominates credit score and age in distance- or gradient-based models.

Format standardization & correcting inaccuracies

All dates → YYYY-MM-DD; weights → kg; lengths → m; city names → one canonical spelling. Fix misspellings by manual review or automated correction (lookup tables, pattern / fuzzy matching).

state_map = {'Texass': 'Texas', 'NY': 'New York'}
